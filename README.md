# Willowvale: Animal Town

A mobile-first illustrated animal-town life-sim for children, with original characters, six island towns, optional cloud saves, emoji-only chat and a reproducible Android debug APK workflow. Coins only, no real money.

## Included

- Illustrated 2.5D island town drawn on a 2D canvas (no 3D library, no image downloads): four districts (Willow Park, Old Town, Bluewater Quay, Fernhill Heights), a town square, eight places to visit, twelve homes, the Sunwheel and the windmill.
- Twelve original animal neighbours who wander, react and can be befriended; choose your own animal and outfit.
- Daily activities at each place, a bag of items, neighbour gifts, friendship hearts and daily goals.
- Tap-to-walk with pathfinding, drag to pan, pinch or scroll to zoom, WASD/arrow keys on desktop. Phone-first layout with bottom sheets.
- Optional cloud saves: nickname + password accounts (no email), bcrypt password hashes, JWT sessions, rate limits, security headers, versioned saves with conflict detection and account deletion, stored in MongoDB when MONGODB_URI is set.
- Socket.IO online presence per town (how many players are in a town right now).
- Capacitor Android wrapper and GitHub Actions APK artifact build.

## Local development

Requires Node.js 20+. Accounts need MongoDB: a free Atlas M0 cluster works. For local testing set MONGODB_URI=memory://test (an in-memory stand-in; data disappears on restart). With no MONGODB_URI the game runs in guest mode.

    cp .env.example .env
    npm install
    npm start

Open http://localhost:3000. Pick an animal and start exploring as a guest; guest progress is kept on the device. Creating an account (nickname of 3–20 letters, numbers or underscores and an 8+ character password) needs MONGODB_URI. The game code has no CDN dependencies, so it also runs offline inside the Android shell; the Google Fonts stylesheet is optional and falls back to system fonts.

Code layout: public/js/world.js (map, districts, homes, places, neighbours, pathfinding), public/js/art.js (all procedural art), public/app.js (engine, input and UI).

## Deploy to Render

render.yaml describes the live free web service (no paid plans, no Render database).

1. Create a free MongoDB Atlas M0 cluster, a database user with readWrite on the `willowvale` database, and allow access from 0.0.0.0/0 (Render's free plan has no fixed IP).
2. In the Render dashboard set MONGODB_URI to the cluster's connection string. JWT_SECRET is generated by the Blueprint.
3. ALLOWED_ORIGINS defaults to the Render address; add any other frontend origins.
4. Check /healthz: `accounts: true` and `database: connected` mean cloud saves are on; `accounts: false` means guest mode. Watch the `accounts` field, not just the status code, because guest mode still returns 200.
5. Before a public launch for children: privacy policy, parental consent, data deletion, moderation and backups.

## Android APK

GitHub Actions workflow .github/workflows/android-apk.yml generates a Capacitor Android shell, builds a debug APK, and uploads it as an artifact. Open GitHub Actions, select Android APK, open the latest successful run, and download the willowvale-debug-apk artifact.

This is a debug APK for testing, not a signed Play Store release. A signed release needs a protected Android signing keystore and GitHub secrets. Never commit keystores or passwords.

## Prototype limitations

- Personal worlds: each player has their own copy of every town, so homes bought in one save never affect another player. Multiplayer today is online presence only, not shared movement or shared building.
- Saves are checked for shape, size and format version on the server, but coins and progress come from the player's own device. That is fine for personal worlds; anything shared between players (trading, rankings, a shared economy) must be checked on the server.
- Do not treat this as a child-safe public production service yet.
- Characters and buildings are procedural vector art. Sound, real-device performance QA and further accessibility testing remain.
- Public child access requires legal/privacy review, reporting/moderation, data deletion and abuse protection.
